# Chromium 扩展怎样使用用户自己的 ChatGPT 订阅

核查日期为 2026 年 11 月 24 日。这里的“只安装扩展”允许用户首次在 OpenAI 页面登录并授权，无需输入 API 密钥、安装本机程序或启动服务。本次核查了项目源码、发布页面和平台文档，未使用真实账户登录或核对账单。

**和 Margin 最接近的是 Shizue。** 用户从 Chrome 侧栏登录 ChatGPT，就能用自己的订阅总结网页、翻译和对话。它有公开发行的扩展，浏览器直接向 OpenAI 发送推理请求，开发者无须代付或中转。这个产品证明纯扩展可以实现这样的体验。它在浏览器内处理回环回调并持久保存令牌，这两项与 OpenAI 公开的开源接入指南有差异。能确认的官方支持覆盖订阅授权和推理接口，尚无一手证据确认这两项扩展适配也获支持。[Shizue 商店页面](https://chromewebstore.google.com/detail/mpcbgfkoholfgapcgcmfjobnfcbnfanm) · [作者隐私说明](https://github.com/rokrokss/shizue-extension/blob/59248a032ecd35fa122641898aeb7c9a638abd5d/privacy_policy.md) · [OpenAI 注册指南](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) · [OpenAI 会话指南](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)

## Margin 可以复用什么

**订阅与请求。** OpenAI 为开源本机应用提供动态注册。首次使用时，应用以自己的名称发起授权，用户选择账户和工作区，单独批准计划用量权限。应用用 PKCE 交换授权码，验证身份令牌和实际获批的范围，再以访问令牌调用公开的 `/v1/responses`。开发者和用户均无须提供 API 密钥。Margin 的 Quick 或 Full 讨论可以将所需上下文随请求发送，使用 `store: false` 和 `stream: true`。最终验收须收到完整响应；仅登录成功或列出模型仍不足以验证实际推理。开发者快速入门明确列举符合条件的 Plus 和 Pro，用户文档对部分参与产品还列有 Go 和 Business。Margin 能承诺哪些账户可用，取决于实际获批权限和模型目录。[开源接入说明](https://developers.openai.com/siwc/token-sharing-open-source) · [快速入门](https://developers.openai.com/siwc/quickstart) · [模型与推理](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) · [用户文档](https://learn.chatgpt.com/docs/sign-in-with-chatgpt)

**接收授权结果。** Chrome 的标准 `identity.launchWebAuthFlow` 把授权结果交还给扩展时使用 `https://<扩展 ID>.chromiumapp.org/*`。OpenAI 开源自助流程明确要求应用先在 `127.0.0.1` 启动 HTTP 监听，再打开浏览器。常规 Manifest V3 扩展没有创建 TCP 监听器的直接套接字能力。Shizue 把回环返回的处理移入浏览器，因此省去了额外安装。所查官方文档没有将这种方法、Chrome 的专属回调或设备码列为开源订阅自助流程的替代回调。[Chrome 身份接口](https://developer.chrome.com/docs/extensions/reference/api/identity#method-launchWebAuthFlow) · [Chrome 对扩展能力的说明](https://developer.chrome.com/docs/iwa/connect-to-extensions) · [OpenAI 回调要求](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)

**保存和续期。** OpenAI 要求持久令牌位于用户控制的本地环境，会话指南还明确写明 “Keep tokens out of browser storage”。其参考做法是运行时按账号和工作区保留注册信息，在受保护的本机存储保管令牌，同一会话串行刷新并保存最新令牌，退出时撤销会话并清理本地凭据。Shizue 使用的 `chrome.storage.local` 能跨浏览器重启保存登录；Chrome 文档说明该区域默认对内容脚本开放，可限制为可信扩展上下文。这种访问限制与 OpenAI 对令牌存放位置的要求是两个独立问题。内存型 `storage.session` 在浏览器重启时清空，也无法单独提供跨重启登录。[OpenAI 会话指南](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions) · [SIWC 条款第 1 节](https://openai.com/policies/sign-in-with-chatgpt-terms/) · [Chrome 存储接口](https://developer.chrome.com/docs/extensions/reference/api/storage#storage-areas)

**产品决策。** 保留“只安装 Margin”时，值得向 OpenAI 确认两个具体问题：能否为这个扩展登记 Chrome 的 HTTPS 回调，以及允许纯扩展用什么方式保存刷新令牌以支持跨重启登录。公开商业伙伴入口可申请，但申请本身不能证明这些能力已经开放。若条件允许用户另装本机程序，则 Browser Control 已展示出可验证的分工：侧栏处理阅读与交互，本机进程接收登录结果、持有令牌并调用模型。引入该组件会改变 Margin 的单一扩展安装目标。[商业接入入口](https://openai.com/form/sign-in-with-chatgpt-interest/) · [Browser Control 架构](https://github.com/07rjain/browser-control/blob/5bacfe56066b84d10c47e6a03123708b07acf787/docs/decisions/0001-native-codex-bridge.md)
