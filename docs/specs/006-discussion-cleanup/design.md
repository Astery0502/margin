# 关闭标签页时清理讨论

每篇有讨论的文档只登记一个负责清理的标签页。一个标签页可以负责多篇文档。

- **创建讨论**时，后台向浏览器核对发起请求的标签页网址，匹配选区的 `sourceId` 后创建会话。首次创建时一并保存标签页 ID。创建和发送都移除对全局标签页同步的等待。
- **刷新或跳转**只更新当前页面的显示。从文章 A 跳到文章 B，A 的讨论仍归这个标签页清理。
- **关闭标签页**时，后台只处理登记在该标签页下的文档。通过浏览器一次读取其余标签页的网址，PDF 阅读器按原文档网址匹配。仍在其他标签页打开的文档，把登记转给其中一页。其余文档由现有清理逻辑停止任务、删除讨论和关联数据。

创建、移交和清理共用现有的按 `sourceId` 串行机制。移交后核对接手的标签页仍在，同时关页时继续处理该文档。

验收覆盖两个场景。一是让无关标签页始终不回复页面身份查询，当前页仍能创建会话并进入发送。二是在同一标签页从 A 跳到 B，再关闭该页，只有仍在另一标签页打开的文档会保留，关闭最后一页后完成清理。
