# Margin Connect 跨平台账户连接设计

## 用户体验

macOS 和 Windows 共用一个 Chromium 扩展。用户安装扩展后就能阅读网页和 PDF、选段、写草稿。首次需要模型时，连接页提供适合当前系统的 Connect 安装包。用户运行一次安装程序，再选择用自己的 ChatGPT 订阅或 DeepSeek API 密钥。两种连接可以同时存在。

连接成功后回到原标签和草稿，由用户点击发送。此后，浏览器按需启动 Connect。用户在浮窗和侧栏之间切换时，已经发出的请求继续运行；点击停止或关闭来源时，释放对应请求。电脑或浏览器重启后，用户回到同一系统账户，可以直接提问。系统凭据库锁定时保留草稿，提示解锁后重试。

## 职责与请求路径

| 位置 | 负责的工作 | 可以接触的数据 |
| --- | --- | --- |
| 扩展里的阅读界面与 Agent 工作线程 | 组织选段、历史和工具，使用 `pi-agent-core` 驱动对话，用 `pi-ai` 生成请求、解析流式回答 | 原文、草稿、模型和回答 |
| 扩展自己的连接页与后台 | 发现 Connect、打开授权页、提交用户主动输入的密钥、转发请求与停止事件 | 可展示的账户状态；连接页仅在提交时短暂接触新输入的 DeepSeek 密钥 |
| Go 版 Margin Connect | 接收订阅登录回调、验证身份、刷新与撤销令牌、校验模型请求目的地，向提供方发送请求 | 该提供方的凭据，以及完成本次操作需要的请求内容 |
| 系统凭据存储 | 在同一系统用户下为 Chrome 和 Edge 提供同一份受保护的账户记录 | ChatGPT 会话和 DeepSeek 密钥分别保存 |

一次提问沿现有路径执行：工作线程用 `pi-ai` 构造请求，经扩展后台把请求体交给 Connect；Connect 绑定当前账户，向指定提供方发送 HTTPS 请求，逐段传回回答。每条流持有独立端口，端口关闭即取消对应的上游请求。浏览器通过原生消息启动宿主并使用标准输入输出通信。只有 ChatGPT 登录期间会短暂监听本机回环地址。用户无需安装 Pi、Node 或配置端口。[现有模型请求](../../../extension/providers/stream.js) · [原生消息协议](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)

ChatGPT 沿用 Margin 自己的授权身份、PKCE、回调状态和身份令牌校验，以及已登记账户的重新授权。DeepSeek 密钥通过 Connect 调用模型列表接口验证，成功后才保存。两种凭据都由 Connect 加入提供方请求；扩展的账户查询只返回展示信息、可用模型和账户变更序号。宿主仅接受发行配置列出的扩展来源和已定义的操作，提供方地址由宿主确定。日志、讨论记录和导出均排除密钥、令牌、授权码与完整授权地址。[现有订阅授权](../../../companion/oauth.go) · [现有 DeepSeek 接入](../../../companion/deepseek.go)

## 安装、发现与升级

| | macOS | Windows |
| --- | --- | --- |
| 安装与登记 | 沿用双架构应用包，登记当前用户的 Chrome 和 Edge 宿主清单。安装到稳定位置，浏览器实际启动的宿主使用稳定签名标识。 | 提供按当前用户安装的签名安装程序，宿主放在当前用户的本地应用目录。分别在 Chrome、Edge 的 `HKCU` 原生消息注册表项登记清单的绝对路径。 |
| 凭据保护 | 使用登录钥匙串中由 Connect 创建的本机条目，直接调用 Security.framework。正常读取使用应用身份授权，无需每次提问确认。集成时相应调整当前关闭 cgo 的构建方式。 | 使用当前用户范围的 DPAPI，静默加解密。密文文件及其目录使用该用户的访问控制；保护范围是 Windows 用户，同一用户下取得密文的程序也可能解密。 |
| 发布验收 | 使用正式 Developer ID 签名和公证的下载包，验证升级后宿主仍可访问原条目。 | 验证标准用户从实际下载入口完成安装、浏览器发现和覆盖升级。安装器处理正在使用的宿主文件，待旧进程退出后完成替换。 |

两个平台使用同一个宿主名 `dev.margin.connect` 和同一套消息。扩展发布包内置按平台选择的下载地址，下载物单独发布。连接页先发一个不读取凭据的能力查询，确定宿主支持本次提供方及系统存储。宿主缺失时显示安装入口；旧宿主不认识该查询时显示更新入口；权限被拒或浏览器策略阻止连接时显示相应原因。连接页沿用安装期间限时检测和手动重试。已有账户也必须经过能力查询，旧宿主不会被新版扩展用于保存或发送凭据。[Chrome 登记方式](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging) · [Edge 登记方式](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging) · [钥匙串与签名身份](https://developer.apple.com/library/archive/technotes/tn2206/_index.html) · [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)

## 凭据、并发与退出

沿用现有 `vault.transaction` 的调用方式，把跨进程锁、平台存储和旧数据迁移集中在账户存储模块。每个提供方各有一条受保护的记录。ChatGPT 的安装标识、已登记账户、当前选择、访问令牌、刷新令牌、权限、到期时间和账户变更序号一起提交；DeepSeek 单独提交密钥和自己的序号。首次写入和后续替换都以整条记录为单位。macOS 更新单个钥匙串条目，Windows 先加密，再将临时密文原子替换到正式位置。[当前事务及流式会话监测](../../../companion/storage.go)

- **并发与刷新。** 同一用户的多个 Connect 进程按提供方分别加锁。获取锁后重新读取最新状态，再决定是否刷新；一次成功的轮换必须先持久化，才能用新令牌发起模型请求。普通刷新保持账户序号，切换、断开或确认授权失效时递增序号。瞬时网络错误保留原会话。若提供方已经轮换令牌而本机提交失败，提示恢复存储并重试；原令牌也已失效时引导重新授权。
- **正在生成的回答。** 发送时校验扩展携带的账户序号；流式任务继续按现有取消机制检查当前序号。第一版由存储模块读取同一份已提交记录，只向监测调用方返回连接状态和序号。钥匙串读取采用无交互方式，避免后台状态探测触发系统弹窗。存储不可访问时停止受影响的请求并提示恢复，已有记录保留。持续流式读取的开销在真机验收中测量。
- **断开。** 用户在任一浏览器断开某个提供方，会影响同一系统用户的另一浏览器。ChatGPT 在锁内清除令牌、更新序号并保留再次授权所需的注册信息，随后用内存里的刷新令牌请求远端撤销。界面分别报告本机清除和远端撤销结果。DeepSeek 的“忘记密钥”清除本机副本；作废密钥在 DeepSeek 账户中进行。两者独立，断开一方时另一方的任务继续。
- **卸载。** 移除浏览器扩展只影响该浏览器。卸载 Connect 时说明影响已登记的浏览器，在仍能访问系统存储时执行账户清理、报告撤销结果，再移除宿主登记与程序。系统存储锁定导致清理失败时保留可重试的清理入口。

## 已安装用户的迁移

旧版 macOS 把两种账户分别写入 Connect 目录下的 `session.json` 和 `DeepSeek/session.json`。迁移需要同时照顾可能还在运行的旧宿主，以及只配置一个提供方、两个都配置、已退出但保留注册信息的用户。

1. 安装升级先切换新进程的启动入口，等待两个浏览器中的旧宿主结束后才允许首次迁移。旧宿主仍占用流或登录端口时提示结束当前操作；无法确认已退出时，引导用户关闭相关浏览器再继续。这样旧进程不会在迁移后重新写出令牌。
2. 每个提供方独立获取与旧实现兼容的文件锁，读取旧记录。新平台存储中尚无记录时，把完整旧状态写入新位置，回读并核对；确认成功后才清理旧文件。读取、写入或核对失败时保留恢复材料，返回可重试错误，暂停该提供方的模型请求。
3. 新记录内带格式版本和迁移来源标记。若写入后进程退出，重试时先核对已提交记录，再清理残留旧文件。清理失败则继续提示重试。带断开状态的新记录同样具有优先权，避免把旧凭据重新导入。Windows 新装直接创建受保护记录。迁移验收只承诺清理当前安装持有的旧文件，历史系统备份按用户自己的备份策略处理。

## 验收

| 场景 | 可以观察到的结果 |
| --- | --- |
| 干净的 macOS、Windows 用户分别在 Chrome 和 Edge 从草稿首次连接 | 扩展给出正确安装包；安装后自动继续。ChatGPT 和 DeepSeek 均能独立连接，返回原草稿时提问次数为零。点击发送后收到可停止的流式回答。 |
| 正常读取与升级 | 连续发送、重启浏览器和正式签名包覆盖升级后，已连接账户可直接使用。生成期间后台轮询不会反复弹系统提示。人为锁定钥匙串或拒绝访问后保留草稿，恢复权限后可重试。 |
| 原有 macOS 数据迁移 | 用测试凭据覆盖单提供方、双提供方和已退出账户；分别在新记录提交前、提交后和清理失败时中断重试。最后能识别原账户，活动目录无旧明文，已退出会话不会恢复。 |
| 两浏览器并发 | 两端同时遇到即将过期的令牌，只发生一次有效轮换；一端断开后另一端的旧流终止，旧请求不能借新账户继续。另一提供方仍然可用。 |
| 安装和撤销失败 | 旧宿主、登记缺失、存储锁定分别给出正确动作。模拟远端撤销失败时，界面准确说明本机清除结果。卸载后浏览器不再找到宿主。 |

自动化优先扩展已有连接测试，用受控提供方验证刷新、断开和迁移中断。两端的签名识别、凭据读取提示、跨浏览器发现与真实升级，使用从发布入口下载的安装包在标准用户环境验收。以上均为本次设计的验收条件。[现有连接检查](../../../checks/connect.mjs)
