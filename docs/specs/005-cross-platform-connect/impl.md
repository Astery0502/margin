# 跨平台账户连接实现记录

扩展和 Go 宿主沿用原生消息协议。新版连接页先查询宿主能力，再按系统显示安装或更新入口。账户与模型操作使用带版本的操作名，旧宿主会拒绝执行。首次连接完成后回到原草稿，用户点击发送才产生模型请求。

## 存储与安装

- macOS 使用 Security.framework 直接访问当前用户的默认钥匙串，通常为登录钥匙串。每个提供方各有一个条目，后台访问关闭系统交互。安装程序保留旧宿主文件的硬链接，直到旧进程退出；安装中断后再次运行可完成替换。
- Windows 安装包包含 x64 和 Arm64 宿主，按当前用户登记 Chrome 和 Edge。每个提供方的记录由用户范围的 DPAPI 加密，临时密文写入后替换正式文件；流式读取允许并发替换。卸载入口在清理凭据后移除登记。
- 各提供方在跨进程锁内更新账户或刷新令牌。首次访问旧账户时完整迁移，核对受保护的回读记录后再删除旧文件。清理未完成时，在下次访问重新核对。卸载与活跃请求互斥；单独断开账户时，其他浏览器的对应流会发现会话已结束。

## 验证与发布状态

macOS 的 Go 竞态测试使用隔离的合成账户和真实钥匙串。覆盖令牌失效、并发刷新、已退出账户迁移、迁移回读不一致、升级中断恢复和卸载互斥。隔离 Edge 通过实际原生消息连接受控提供方，覆盖授权校验、连接后返回草稿、流式回答、浏览器重启、独立断开和撤销。Windows 更新入口在 Edge 中用模拟平台信息验证。阅读、讨论、文件和听写另走既有浏览器回归。

Windows 两种架构的宿主和 Go 测试程序已交叉编译并通过静态检查，已生成含两种宿主的 NSIS 安装包。仓库提供 `npm run check:windows`，在干净的 Windows 用户下验证实际安装、两份登记、原生消息、DPAPI 状态跨升级保存和卸载。本轮工作环境为 macOS，Windows 原生执行、两款浏览器从实际发行渠道安装，以及正式签名升级后的钥匙串访问仍待实机验收。本轮模型请求使用受控账户。

`dist-native/Margin-Chromium.zip` 包含可加载的 `dist` 目录和两个平台的本地安装包。当前 macOS 包使用开发用临时签名，Windows 包未签名。正式构建的签名、下载地址和运行命令见[项目说明](../../../README.md)。

## 简化审查

完成首轮测试后运行 `simplify`。修正了升级中断后无法重试、迁移重试核对不完整和 Windows 安装器跳过宿主文件的问题。原生消息版本编码和旧宿主识别集中到同一处；流式任务直接读取已提交的受保护记录，安装页复用本次打开时读取的下载清单。
